Credential Dumping — Threat Intelligence Reference
====================================================

MITRE ATT&CK: T1003, T1003.001 (LSASS), T1003.002 (SAM), T1003.003 (NTDS), T1003.006 (DCSync)
Severity: CRITICAL — credential dumping almost always leads to full domain compromise

Overview
--------
Credential dumping extracts authentication credentials (plaintext passwords, password hashes, 
Kerberos tickets) from operating system memory, registry, or files. It is one of the most 
impactful post-exploitation techniques because it enables lateral movement and privilege escalation 
across the entire environment.

Primary Techniques
------------------
1. LSASS Memory Dump (T1003.001)
   - The Local Security Authority Subsystem Service (LSASS) stores credentials in memory.
   - Tools: Mimikatz (sekurlsa::logonpasswords), ProcDump (-ma lsass.exe), Task Manager,
            comsvcs.dll (rundll32 comsvcs.dll MiniDump), nanodump, pypykatz.
   - Indicators: procdump.exe or lsass.dmp in filesystem, Event ID 4656 (handle to lsass),
                 Sysmon Event ID 10 (process access to lsass.exe).
   - Detection: Alert on any process accessing lsass.exe with PROCESS_VM_READ permission
                that is NOT a known security product.

2. SAM Database (T1003.002)
   - The Security Account Manager (SAM) stores local account hashes.
   - Access requires SYSTEM privileges and offline mount or Volume Shadow Copy.
   - Tools: reg save HKLM\SAM, secretsdump.py (Impacket).
   - Indicators: reg.exe accessing SAM hive, vssadmin commands to access shadow copies.

3. NTDS.dit Dump (T1003.003) — Domain Controller
   - NTDS.dit contains all Active Directory credential hashes.
   - Compromise of this file = compromise of every account in the domain.
   - Tools: ntdsutil.exe, vssadmin create shadow, secretsdump.py.
   - Indicators: ntdsutil.exe execution, shadow copy creation on DC, large file transfer.

4. DCSync Attack (T1003.006)
   - Simulates a Domain Controller replication request to pull all user hashes.
   - Does not require code execution on DC — any account with Replication rights is sufficient.
   - Tools: Mimikatz (lsadump::dcsync), secretsdump.py with valid credentials.
   - Indicators: Event ID 4662 (object operation) with Replicating Directory Changes permissions
                 from a non-DC workstation.

5. Kerberoasting (T1558.003)
   - Requests Kerberos service tickets for service accounts (SPNs).
   - Ticket is encrypted with service account's NTLM hash — cracked offline.
   - Tools: Rubeus, GetUserSPNs.py (Impacket), PowerView.
   - Indicators: Unusual spike in TGS requests (Event ID 4769) from a single workstation.

6. Pass-the-Hash (T1550.002) — Post-Dump Exploitation
   - After dumping, attackers authenticate using the NTLM hash directly without cracking.
   - Tools: Mimikatz (sekurlsa::pth), wmiexec.py, psexec.py.
   - Indicator: Authentication attempts using NTLMv1 from unusual sources.

Detection Signals
-----------------
- Sysmon Event ID 10: Process accessed lsass.exe (source: suspicious process)
- Windows Event ID 4656/4663: Handle requested to LSASS process
- Windows Event ID 4662: Replication rights used on Domain Controller
- Windows Event ID 4769: Kerberos service ticket request spike
- Presence of: procdump.exe, mimikatz.exe, lsass.dmp, NTDS.dit outside DC
- Execution of: rundll32 comsvcs.dll, vssadmin, ntdsutil
- Network: Large SMB transfers from DC, unusual DRSUAPI traffic

Response Actions
----------------
1. Immediately isolate the affected host — assume all cached credentials are compromised.
2. Force password reset for ALL accounts that logged into the affected host.
3. Rotate all service account passwords and Kerberos service tickets (klist purge).
4. If DCSync detected: Reset krbtgt account password TWICE (invalidates all Kerberos tickets).
5. Review and revoke any elevated privileges granted recently.
6. Hunt for lateral movement using the dumped credentials (check logon events from new hosts).
7. Preserve lsass.dmp for forensic analysis if safely retrievable.
8. Enable Windows Credential Guard to protect LSASS from memory access.

SOAR Playbook
-------------
Trigger: Process access to lsass.exe from non-security process, OR procdump execution,
         OR Mimikatz indicators in process name/arguments.
Auto-actions: (1) Create CRITICAL incident, (2) Isolate host from network,
              (3) Page on-call analyst immediately, (4) Snapshot host memory for forensics.

Prevention
----------
- Enable Credential Guard (Windows 10/Server 2016+) — protects LSASS with virtualization.
- Enable Protected Users security group for privileged accounts.
- Remove local admin rights from standard user accounts.
- Implement LAPS (Local Administrator Password Solution) for unique local admin passwords.
- Restrict Replication rights strictly to Domain Controllers only.
- Disable NTLMv1; enforce NTLMv2 at minimum, prefer Kerberos.

Related CVEs
------------
- CVE-2021-36934 (HiveNightmare/SeriousSAM): Unprivileged read of SAM/SYSTEM on Windows 10/11.
- CVE-2020-1472 (Zerologon): Unauthenticated DCSync equivalent — reset DC machine account.
- CVE-2014-1812: Group Policy Preferences storing credentials in SYSVOL (GPP passwords).
